# Factory

Read [the learning contract](../../references/learning-contract.md) and
[paper practice](../../references/paper-practice.md) before acting.

## `sisyphus factory <COURSE> [topic] [count=10]`

1. **Target.** Read the course MOC, `resource_guide`, prerequisite track and actual
   performance evidence. Prefer the named topic; otherwise use recorded weak
   topics. Never infer mastery from an A-level grade or from time spent. IZP starts
   at the first unpassed C stage and keeps the full pointer week.
2. **Choose the supply.** Existing external exercises or author simulators may
   already provide the requested volume with checkable keys. Use their stable
   exercise IDs or simulator version, arguments and seeds. Bank the selected
   exercises before a drill draws them. If the request specifically asks for new
   variations, generate original ones without reading reserved FIT papers. Never
   reuse or complete a student's current graded project as an exercise.
3. **Verify before issue.** An AI-generated key needs independent checking: another
   authorized model family solves it independently, or an appropriate deterministic
   checker establishes the answer (for example exhaustive truth tables, algebraic
   substitution, or compiled ungraded C with tested inputs). A model repeating its
   own reasoning is not independent verification. For proofs and modelling rubrics,
   a numeric spot-check is insufficient. Check task clarity, alternative valid
   answers, diagrams, stated marks, prerequisites and duplicate items. Drop any
   unresolved item. Generated difficulty is not calibrated FIT difficulty.
4. **Optional model seats.** Inspect locally available routes and the user's
   existing authorization first. Do not assume old model IDs or subscriptions
   work. Do not install tools, send data to another service, spawn agents, use a
   metered API or switch to a paid fallback merely because an old brief named it.
   With no authorized independent verification route, use supplied checked
   exercises or report the concrete verification gap. Do not ship unverified keys.
5. **Ship a practice pack.** Store questions and sealed solutions under the course's
   private corpus, with collision-safe IDs and source/check provenance. A requested
   timed pack uses `drill new ... practice` and its immutable attempt contract.
   If an existing checkpack harness is available, inspect its actual accepted
   format before producing a compatible pack; never invent a command. A sequential
   tutor session reveals one question and one hint rung at a time, never its answer.
6. **Report** selected/generated, kept, corrected and rejected counts, the paths,
   verification method and chosen solving budget. No preview of a sealed pack.

## Volume with learning

Start with focused repetitions until the method is understood, then mix methods so
Samuel must choose one. Record repeat exposure honestly. A later fresh unaided
question checks transfer. Neither a long session nor a high question count alone
creates a card or passes a prerequisite. Ninety minutes is the default session;
Samuel may explicitly choose more. No daily paper-count limit is imposed.
